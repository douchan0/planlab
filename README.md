# PlanLab

**A mechanism-switchable computational laboratory for planned-economy coordination.**

[![licence: MIT](https://img.shields.io/badge/licence-MIT-blue.svg)](LICENSE)
[![python](https://img.shields.io/badge/python-3.10%2B-blue.svg)](pyproject.toml)

PlanLab is not a simulator of "the planned economy". It is a controlled
environment in which **the institution is the treatment**: the same Leontief
input–output technology, the same shocks, the same information delay and the same
accounting are given to six different coordination mechanisms, and the resulting
shortage, welfare, plan-fulfilment and stability are compared.

The scientific question it was built to answer:

> **How does delay in the information available to a central coordinator — how
> stale and noisy the planner's picture of demand, capacity and inventories is —
> affect the stability and welfare performance of alternative coordination
> mechanisms in an input–output economy; and which mechanism damps, and which
> amplifies, the resulting shortage dynamics?**

## The model in one paragraph

An `n`-sector economy in discrete quarters. Technology is Leontief with a direct
input matrix `A` from a published symmetric I-O table and capacity
`x̄ = K/κ`. Each period: a shock hits capacity or demand; the coordinator observes
a **stale, noisy** picture of the economy (`k` reporting lags plus log-normal
measurement error); it forms output targets, files claims on every good with a
priority ladder, and sets next period's prices. The engine then determines the
*short side* — the largest feasible output vector given capacity, inventories and
the claims that outrank production inputs, which is a small linear programme — and
rations the residual by priority. Everything is audited every period: the identity
`S₀ + x = Σⱼ Zⱼ + C + G + I + S_end` must hold to 1e-8 relative or the run aborts.

## The six institutions

| id | institution | historical referent | information it needs |
|---|---|---|---|
| `lp_central` | welfare-maximising central LP, shadow prices as the price signal | Kantorovich, central material balances | the full current state |
| `material_balance` | resource–need balancing with proportional target revision | Gosplan material balances | plan targets + observed stocks |
| `rationing_priority` | administrative quotas, strict priority | rationing and quota systems | last period's returns |
| `tatonnement` | price board adjusting prices to excess demand | Lange's market socialism (CPB) | prices + observed gaps |
| `market` | within-period Walrasian tâtonnement | competitive benchmark | current prices |
| `hybrid_dual_track` | plan track at administered prices for share θ, market track for the rest | dual-track reform | both |

Because the mechanisms differ only in *who decides what*, and because all of them
receive the same observation object and face the same shock stream, differences in
outcomes are attributable to the institution.

## Quick start

```bash
git clone <this repo> && cd planlab
python3 -m venv --system-site-packages .venv
.venv/bin/python -m pip install -e ".[dev]"
source scripts/env.sh

python -m planlab.cli list-mechanisms
python -m planlab.cli show-technology --source eurostat
python -m planlab.cli run scenarios/baseline_mb_k0.yaml --trace
```

Rebuild the data from the source:

```bash
python -m planlab.data.build --source eurostat     # idempotent, caches the raw JSON-stat
```

Reproduce the paper end to end:

```bash
bash scripts/reproduce.sh          # or: make reproduce
```

Run the tests, and the teaching notebooks:

```bash
.venv/bin/python -m pytest tests/ -q
.venv/bin/python notebooks/execute_all.py     # six executed notebooks, ~30 s
```

The notebooks are the fastest way into the model: `notebooks/README.md` has a
three-hour teaching sequence, and `03_one_period_walkthrough.ipynb` re-derives a
single period from the written specification and checks it against the engine
bit-for-bit.

## What the paper claims

Four findings the design is built to test:

1. **Delay has a closed-form cost.** For a signal revised in proportion to an
   observed gap with effective delay `m` periods, the loop is stable iff the loop
   gain `g < g*(m) = 2 sin(π/(2(2m+1)))`, and at the boundary it oscillates with
   period `2(2m+1)`. Since `g*(m) ~ π/(2m+1)`, **doubling the delay roughly halves
   the admissible gain** — the first period is the expensive one (2 → 1), and it is
   the product `m·g*` that delay bounds, at `π/2`, not the gain alone.
2. **Taut plans are self-defeating.** In a capacity-constrained input–output
   economy the revision of *output targets* is a positive feedback loop: raising
   targets raises intermediate demand, which raises shortage, which raises targets.
   Measured on the real table, mean shortage rises monotonically with the revision
   gain.
3. **Mechanisms separate along information demand, not along ideology.** The
   omniscient planner has the best outcomes at `k = 0` and the steepest degradation
   in `k`; material balance, which plans from stocks rather than from current demand,
   is the most delay-tolerant.
4. **Who bears the shortage is not who causes it.** Intermediate inputs outrank
   consumption in a mobilisation ladder, so a supply shock that costs 2% of output
   can cost a third of final deliveries of the affected good.

The pre-registration (`docs/PROTOCOL.md`), its amendments (`docs/AMENDMENTS.md`),
the analytics (`docs/notes_delay_theorem.md`) and the independent verification
(`verification/`) are all in the repository, including the predictions that failed.

## Reproducibility contract

* Every scenario is a self-describing YAML file; `planlab run <file>` reproduces it
  standalone.
* Every run is seeded deterministically from `(scenario_id, seed)`, and mechanisms
  inside a cell share the same exogenous stream (common random numbers), so
  mechanism comparisons are paired.
* `data/metadata/manifest.json` records the source URL, the sha256 of the raw
  response and of the aggregation map, so a silent upstream revision is detectable.
* `results/*/manifest.json` records package versions, scenario hashes and seeds.
* No number in a table is typed by hand; tables are generated from `results/`.

## Known limitations

Stated because they bound what the paper can claim: all quantities are
constant-price value units, not physical volumes; the technology is a single-year
Leontief table with no substitution; there is no money, credit or finance; households
do not optimise intertemporally; firms do not game plan indicators (the classic
"output tonnage" pathology is future work); and the model is a closed economy, so
net exports are absorbed into final demand.

## 中文摘要

**PlanLab 是一个"制度可替换"的计划经济协调机制计算实验平台。**

它并不试图复刻某个历史国家的全部制度，而是把**制度写成一个可替换的模块**：同一套列昂惕夫投入产出技术、同一组冲击、同样的信息延迟与同样的会计标准，分给六种不同的协调机制（中央线性规划/影子价格、物资平衡、行政配额、Lange 式价格试错、竞争市场、计划—市场双轨），比较其短缺、福利、计划完成率与稳定性。

要回答的问题是：**中央协调者所获信息的时间滞后与噪声，如何影响不同协调机制的稳定性与福利表现？哪种机制抑制、哪种放大随之而来的短缺动态？**

核心结论（详见 `paper/`）：延迟有闭式代价（临界增益 `g*(m)=2sin(π/(2(2m+1)))`，边界处振荡周期 `2(2m+1)` 个季度）；在产能受限的投入产出经济中，按观察到的短缺上调产量目标是**正反馈**——"紧绷的计划自我挫败"；机制之间沿"信息需求"而非意识形态分化；且**承担短缺的人不是造成短缺的人**——生产投入优先于消费的阶梯，使一次只让总产出下降 2% 的冲击可能吃掉受影响商品三分之一的最终供给。

全部实验可复现：情景为自描述 YAML，随机种子由 `(scenario_id, seed)` 决定，同一实验单元内各机制共享同一条外生冲击路径（共同随机数），结果与图表全部由代码生成，无手工数字。

```bash
source scripts/env.sh
python -m planlab.cli run scenarios/baseline_mb_k0.yaml --trace
bash scripts/reproduce.sh
```
